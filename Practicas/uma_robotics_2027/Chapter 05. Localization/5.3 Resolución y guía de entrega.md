## 3. Cómo se ha resuelto y por qué

### 3.1. ASSIGNMENT 1: modelo de movimiento

```python
noisy_movement = np.vstack(stats.multivariate_normal.rvs(movement.flatten(), movement_covariance))
return tcomp(pose, noisy_movement)

for particle in particles:
    particle.pose = sample_motion_model(particle.pose, movement, movement_covariance)
```

Se toma una muestra nueva del comando para cada partícula. `np.vstack` mantiene la forma de pose `(3, 1)` y `tcomp` compone el movimiento local con la pose de la partícula.

### 3.2. ASSIGNMENT 2: evaluación del scan

```python
for i in range(pointcloud.shape[1]):
    total_prob *= map.sample_likelihood(pointcloud[0:2, i])

world_pointcloud = LaserUtils.express_as_global_point_cloud(z, pose)
return evaluate_pointcloud(map, world_pointcloud)
```

La función de `LaserUtils` expresa los extremos del scan en coordenadas globales. En esta implementación devuelve dos filas (`x`, `y`); seleccionar `pointcloud[0:2, i]` conserva la coordenada esperada por el campo de likelihood. Se multiplican las probabilidades de todos los extremos, de acuerdo con el modelo del ejercicio.

### 3.3. Evaluación de las tres poses

En la celda 29, cada una de las poses se pasa a `evaluate_pose(occupancy_map, z, pose_particlek)`. La explicación añadida justo después describe la figura: la partícula verde está cerca de la pose real y proyecta los extremos sobre las paredes; las poses azul y magenta están desplazadas y giradas, por lo que muchos extremos reciben likelihoods pequeños y su producto disminuye.

### 3.4. ASSIGNMENT 3: pose y covarianza

```python
position = particle.pose[0:2]
angle = particle.pose[2, 0]
expected_value_position += position * particle.weight
expected_value_direction += np.vstack([np.cos(angle), np.sin(angle)]) * particle.weight
```

La posición se promedia con los pesos normalizados. Para la orientación se promedian los vectores unitarios, no los ángulos directamente: así se evita el error de promediar, por ejemplo, ángulos próximos a `π` y `-π` como si estuvieran cerca de cero.

```python
var_x += particle.weight * (particle.pose[0, 0] - expected_pose[0, 0])**2
var_y += particle.weight * (particle.pose[1, 0] - expected_pose[1, 0])**2
```

La covarianza guarda las varianzas de `x` e `y` y la varianza circular de la orientación, como pide el notebook.

### 3.5. ASSIGNMENT 4: remuestreo

```python
cumulative = np.cumsum([particle.weight for particle in particles])
cumulative[-1] = 1.
r = np.random.uniform(0, 1, M)
selected = np.searchsorted(cumulative, r)
```

La CDF convierte los pesos normalizados en intervalos. `searchsorted` usa `side="left"` por defecto, que asigna cada valor aleatorio al primer acumulado que lo contiene. Las partículas seleccionadas se copian con peso `1/M`.

### 3.6. ASSIGNMENT 5: actualización y filtro completo

```python
particle.weight *= evaluate_pose(map, z, particle.pose)
normalize_weights(self.particles)
```

Cada peso anterior se multiplica por el likelihood del scan desde esa pose y después se normalizan todos los pesos.

En cada movimiento, el bucle completo aplica en orden:

```python
sample(pf.particles, move, cov)
pf.update_weights(occupancy_map, z)
estimated_pose, estimated_covariance = current_estimation(pf.particles)
pf.particles = resample(pf.particles)
```

Primero se predicen las poses; luego se corrigen los pesos con el scan; se calcula una pose y su incertidumbre para dibujarlas; finalmente se remuestrea la población.

## 5. Rarezas del código y del entorno

- **Covarianza cero:** `ParticleFilter` crea las partículas iniciales con `np.diag([0,0,0])`. En el SciPy instalado, `stats.multivariate_normal.rvs` acepta esa matriz singular y genera `[4., 4., 0.]`; la ejecución completa no falla en esa celda.
- **Diferencia numérica pequeña:** el `requirements.txt` del repositorio del profesor fija NumPy 1.23.3 y SciPy 1.9.1; este entorno ejecuta NumPy 2.4.3 y SciPy 1.17.1. La evaluación de partículas hace otro scan láser después de la semilla de la celda 26, y el sensor añade ruido con `np.random.normal`. Es probable que las diferencias de versiones en el muestreo o en la aritmética de punto flotante expliquen las pequeñas diferencias de las partículas 1 y 3. No se pudo confirmar comparando contra esas versiones antiguas.
- **OpenCV:** el intérprete local no tenía `cv2`, aunque el notebook lo importa. Para ejecutar sin alterar el repositorio, se usó temporalmente `opencv-python-headless==4.11.0.86` desde `/tmp/robotica-5.3-deps`; no se modificó `requirements.txt`.
- **Capturas:** las seis figuras generadas se compararon visualmente con las imágenes «Expected output» del notebook; la geometría, las poses y las partículas son coherentes con ellas.
